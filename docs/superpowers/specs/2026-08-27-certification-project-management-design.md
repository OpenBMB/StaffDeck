# StaffDeck 认证项目管理页面设计规格

日期：2026-08-27
状态：设计冻结
实现策略：独立管理员管理页面（方案 A）

## 1. 背景

StaffDeck 已有审核项目（代码模型 `AuditCase`）的后端能力和聊天页项目选择器，但当前前端没有项目管理入口。管理员只能通过 API 创建项目，不能在网页中完成项目创建、材料上传和成员维护。

已核实的现状：

- 后端已经提供项目创建、查询、材料上传、材料处理、覆盖率、报告、归档和删除接口。
- 聊天页已经能够读取用户可访问的项目，并把会话绑定到 `audit_case_id`。
- 数据模型已经保存项目负责人、成员账号 ID、知识库版本 ID、材料版本和事件记录。
- 后端尚无项目基本信息更新接口和成员维护接口。
- 当前项目成员可调用部分材料写入、处理和归档能力，权限范围大于本设计需要的范围。
- 当前材料去重按项目和文件哈希判断，文件版本匹配只看文件名，尚未把材料分类纳入判断。

本设计新增管理员网页管理闭环，不重命名数据库模型和 API 根路径。界面使用“认证项目”，代码继续使用 `AuditCase`、`audit_case_id` 和 `/api/audit-cases`。

## 2. 目标

管理员能够在 StaffDeck 网页中完成：

1. 新建和编辑认证项目。
2. 从当前租户已有内部账号中选择项目成员。
3. 选择项目使用的知识库版本。
4. 分类上传、替换、处理和重试审核材料。
5. 查看材料状态、覆盖率和最近项目事件。
6. 归档或删除项目。
7. 从项目详情直接创建绑定项目的审核对话。

同时保证：

- 普通成员不能修改项目配置或项目材料。
- 项目成员仍可在对话中使用分配给自己的项目。
- 不同项目之间的材料、覆盖率、报告和会话严格隔离。
- 已归档项目保持只读。
- 现有长文档审核流水线和聊天页面继续工作。

## 3. 非目标

本阶段不实现：

- 邀请未注册人员或邮件邀请流程。
- 在项目管理页创建 StaffDeck 账号。
- 通用项目中心或团队模块重构。
- 项目负责人转移。
- Redis、Celery 或其他后台任务队列。
- 审核报告编辑器重构。
- `AuditCase` 数据表和 API 根路径的整体重命名。
- 普通成员参与材料维护的协作工作流。

## 4. 核心决策

### 4.1 独立管理页面

新增管理员专用页面：

- 项目列表：`/enterprise/audit-cases`
- 项目详情：`/enterprise/audit-cases/:caseId`

聊天页只保留项目选择和绑定，不承载完整管理功能。

### 4.2 仅选择已有内部账号

成员来自当前租户的 StaffDeck 内部账号：

- 账号必须属于当前租户。
- 账号 `source` 必须为 `web`。
- 不接受渠道客户、群聊虚拟账号或未注册邮箱。
- 需要新账号时跳转现有“账号管理”页面。

### 4.3 管理与使用分离

项目配置和材料属于管理员维护的受控审核证据；项目成员只获得读取项目、使用项目创建审核对话的权限。

### 4.4 服务端是唯一事实来源

项目归属来自路由 `caseId` 和数据库 `audit_case_id`。不在 LocalStorage 中保存或推断当前认证项目，不使用企业名称作为项目标识。

## 5. 信息架构

### 5.1 导航

管理员左侧导航在“我的团队”之后显示“认证项目”。普通成员不显示该入口。

### 5.2 项目列表

页面提供：

- 新建认证项目。
- 企业名称搜索。
- 项目状态筛选：进行中、已归档、全部。
- 管理体系筛选。
- 报告类型筛选。
- 分页。

列表字段：

- 受审核组织。
- 报告类型。
- 管理体系。
- 项目负责人。
- 项目成员。
- 材料就绪数量、总数和失败数量。
- 文件覆盖率和分块覆盖率。
- 项目状态。
- 最近更新时间。
- 查看、进入对话、归档和删除操作。

点击列表行进入项目详情。破坏性操作必须二次确认。

### 5.3 新建项目

使用三步弹窗：

1. 基本信息：受审核组织名称、报告类型、管理体系。
2. 知识库范围：选择当前租户可用知识库版本。
3. 项目成员：从当前租户已有内部账号中多选。

项目负责人固定为创建项目的当前管理员。创建成功后跳转项目详情，再上传材料。材料不放在创建弹窗中，避免产生没有项目 ID 的临时材料。

### 5.4 项目详情

详情页顶部显示项目名称、报告类型、状态、负责人、成员和主要操作。

详情包含三个页签：

1. 项目概览：基本信息、知识库版本、材料统计、覆盖率、阻断项和最近事件。
2. 项目材料：分类上传、处理、替换、重试和版本查看。
3. 项目成员：搜索、添加和移除已有内部账号。

## 6. 材料分类与生命周期

第一阶段固定支持四种审核流水线材料类型：

| 界面名称 | API 值 |
| --- | --- |
| 审核计划 | `audit_plan` |
| 审核记录 | `audit_record` |
| 绩效及证明材料 | `performance_record` |
| 审核报告模板 | `report_template` |

材料状态在界面中呈现为：

```text
等待上传 -> 上传中 -> 等待解析 -> 文本提取中 -> 证据处理中 -> 已就绪
                                             \-> 处理失败
```

“上传后自动处理”默认开启。前端上传成功后调用单材料处理接口；关闭时仅上传，管理员稍后手动处理。

### 6.1 文件格式和大小

允许：

- `.pdf`
- `.docx`
- `.txt`
- `.md`
- `.markdown`
- `.html`
- `.htm`

旧版 `.doc` 在前端选择后立即提示转换为 `.docx`，后端仍做相同校验。第一阶段单文件上限为 50 MB，前后端都必须验证。

### 6.2 上传并发

- 每个文件单独发起请求并拥有独立状态。
- 最多并发上传三个文件。
- 单个文件失败不阻止其他文件。
- 原生 `fetch` 不提供可靠上传百分比，因此只显示真实阶段，不显示虚假百分比。
- 页面离开时如仍有上传任务，提示用户确认。

### 6.3 去重和版本规则

重复内容判断键：

```text
项目 ID + 材料类型 + SHA-256
```

同名版本判断键：

```text
项目 ID + 材料类型 + 文件名
```

规则：

- 同分类、同内容重复上传返回已有材料，并显示“文件已存在”。
- 不同分类上传相同内容返回 `409 MATERIAL_CATEGORY_CONFLICT`，不静默改变分类。
- 显式替换使用原 `materialId`，不依赖新文件名。
- 替换后旧版本保留，新版本成为当前版本。
- 新报告只使用当前材料版本；历史报告保留原材料版本引用。

为使“材料类型参与版本唯一性”与现有 SQLite 约束一致，需要增加一次幂等、向后兼容的启动迁移，将材料唯一约束调整为包含 `material_type`。本次不新增领域数据表，但会修改现有材料表的约束定义。

## 7. 权限模型

| 操作 | 管理员 | 项目成员 | 非项目成员 |
| --- | --- | --- | --- |
| 查看项目列表 | 当前租户全部 | 仅被分配项目 | 不可见 |
| 查看项目、材料状态 | 是 | 是 | 否 |
| 新建和编辑项目 | 是 | 否 | 否 |
| 维护成员 | 是 | 否 | 否 |
| 上传、替换、处理材料 | 是 | 否 | 否 |
| 归档和删除项目 | 是 | 否 | 否 |
| 在对话中使用项目 | 是 | 是 | 否 |

后端权限是最终边界。前端隐藏按钮和路由重定向不能替代服务端校验。

归档项目只允许读取历史信息，禁止：

- 修改基本信息。
- 修改成员。
- 上传、替换或处理材料。
- 创建新审核报告。
- 创建新的项目审核对话。

## 8. API 设计

### 8.1 保留接口

```text
POST   /api/audit-cases
GET    /api/audit-cases
GET    /api/audit-cases/{caseId}
POST   /api/audit-cases/{caseId}/materials
GET    /api/audit-cases/{caseId}/materials
POST   /api/audit-cases/{caseId}/process
GET    /api/audit-cases/{caseId}/coverage
POST   /api/audit-cases/{caseId}/archive
DELETE /api/audit-cases/{caseId}
```

`GET /api/audit-cases` 保持数组响应，继续供聊天页读取用户可访问项目。

创建、材料写入、处理和归档接口调整为管理员写权限。

### 8.2 管理列表

```http
GET /api/audit-cases/management
```

参数：`tenant_id`、`q`、`status`、`management_system`、`report_type`、`offset`、`limit`。

响应为分页对象，项目条目包含材料统计和覆盖率。后端使用批量聚合，禁止前端对每个项目发起材料统计请求。

### 8.3 管理选项

```http
GET /api/audit-cases/management-options?tenant_id={tenantId}
```

返回管理员可选的知识库名称、版本、状态和版本 ID，以及材料格式和大小限制。账号仍复用 `/api/auth/users`。

### 8.4 编辑基本信息

```http
PATCH /api/audit-cases/{caseId}
```

可更新：

- `organization_name`
- `report_type`
- `management_systems`
- `knowledge_base_version_ids`

不可通过该接口更新负责人或成员。知识库版本必须真实存在、属于当前租户且可用。

### 8.5 替换成员

```http
PUT /api/audit-cases/{caseId}/members
```

请求提交完整 `member_user_ids`。所有成员在一个事务中验证和保存，任一无效账号导致全部回滚。

### 8.6 项目事件

```http
GET /api/audit-cases/{caseId}/events
```

返回项目创建、编辑、成员调整、材料上传、材料处理、归档和报告生成等事件。事件元数据不保存文件全文、模型提示词或密钥。

### 8.7 单材料处理

```http
POST /api/audit-cases/{caseId}/materials/{materialId}/process
```

只处理指定当前材料，用于上传后自动处理和失败重试。

### 8.8 显式替换材料

```http
POST /api/audit-cases/{caseId}/materials/{materialId}/replace
Content-Type: multipart/form-data
```

新文件继承原材料分类并生成新版本。原材料保留为历史版本。

### 8.9 材料历史版本

```http
GET /api/audit-cases/{caseId}/materials?include_history=true
```

默认只返回当前材料；展开历史版本时请求全部版本。

## 9. 错误契约

| HTTP | 错误码 | 界面提示 |
| --- | --- | --- |
| 403 | `AUDIT_CASE_ADMIN_REQUIRED` | 仅管理员可以维护认证项目 |
| 404 | `AUDIT_CASE_NOT_FOUND` | 项目不存在或你无权访问 |
| 409 | `AUDIT_CASE_READ_ONLY` | 项目已归档，不能继续修改 |
| 409 | `MATERIAL_ALREADY_EXISTS` | 该文件已经上传 |
| 409 | `MATERIAL_CATEGORY_CONFLICT` | 相同文件已存在于其他材料分类 |
| 422 | `INVALID_PROJECT_MEMBER` | 所选成员不存在或不是内部账号 |
| 422 | `INVALID_KNOWLEDGE_VERSION` | 所选知识库版本不可用 |
| 422 | `UNSUPPORTED_DOCUMENT_FORMAT` | 文件格式暂不支持 |
| 413 | `AUDIT_MATERIAL_TOO_LARGE` | 单个文件不能超过 50 MB |
| 500 | `MATERIAL_PROCESSING_FAILED` | 材料处理失败，可查看原因后重试 |

前端统一根据错误码映射中文提示，未知错误保留请求 ID 或可诊断信息，不直接展示无上下文的英文异常。

## 11. 防止项目串用

1. 路由 `caseId` 是项目详情唯一标识。
2. 每个材料 API 同时携带 `caseId` 和 `materialId`，后端验证两者归属。
3. 前端接收材料后验证 `material.audit_case_id === currentCaseId`。
4. 切换项目时使用 `AbortController` 取消旧请求，并拒绝迟到响应覆盖新页面。
5. 不在 LocalStorage 保存当前项目。
6. “进入审核对话”先创建包含 `audit_case_id` 的 ChatSession，再跳转返回的 `session_id`。
7. 会话创建后不能改绑其他项目；切换项目必须新建对话。
8. 已归档项目不出现在可创建新对话的选择列表中。

- 项目列表、筛选、分页和 URL 状态。
- 三步创建流程及失败后表单保留。
- 项目详情局部加载失败。
- 成员选择、保存和失败回滚显示。
- 文件格式预校验、独立上传状态、并发限制、自动处理和失败重试。
- 显式材料替换。
- 项目切换时取消旧请求和拒绝迟到响应。

## 14. 风险与缓解

| 风险 | 程度 | 缓解措施 |
| --- | --- | --- |
| 收紧成员写权限影响旧调用 | 中 | 权限回归测试，明确成员只读和使用边界 |
| 大文件同步处理等待较久 | 中 | 单文件处理、独立失败重试；后续按实际耗时评估任务队列 |
| 管理列表形成 N+1 请求 | 中 | 后端批量聚合管理列表 |
| 同名或重复材料版本混乱 | 高 | 分类参与去重和版本键，使用显式替换接口 |
| 旧异步响应覆盖另一项目 | 高 | `caseId` 校验、取消请求和迟到响应保护 |
| 成员移除后权限残留 | 中 | 后端每次请求实时校验，不使用长期项目权限缓存 |
| 归档项目仍被新对话使用 | 中 | 前后端双重验证项目状态 |
| 长文档处理回归 | 高 | 保留 4 万字全文拼接和覆盖率验收测试 |
