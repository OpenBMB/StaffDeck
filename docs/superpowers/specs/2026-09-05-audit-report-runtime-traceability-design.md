# 审核报告运行时与追溯链路 Phase 5A 补充设计

日期：2026-09-05  
状态：已获本轮实施批准  
适用范围：认证项目证据处理入口、报告生成入口、规则版本快照与 Harness 衔接

## 1. 背景与已核实根因

现有审核材料、证据和报告后端服务已经存在，但调用路径没有闭合：

- 材料页的“处理成功”表示材料提取和文本分块完成，不表示证据块已由模型处理。
- 项目级 `POST /api/audit-cases/{case_id}/process` 在材料处理完成后才会运行证据抽取和知识编排；认证项目页面没有调用它的入口。
- 报告创建 API 已能生成章节和发布文件，但项目页面没有生成、版本查看或下载入口；Harness 只有报告状态能力，没有生成能力。
- `AuditReportVersion` 目前只冻结材料版本、知识库版本和覆盖快照，没有冻结项目当前规则绑定或章节实际采用的规则定义。

这不是 `3948add` 引入的回归。Phase 1 计划明确把规则与报告定稿集成延期到 Phase 5；当前规则表为空是管理员尚未创建、发布和绑定业务规则，不能由代码补造规则内容。

## 2. 目标和非目标

本切片目标：

1. 让管理员能够从认证项目页面显式触发证据处理，并看到真实覆盖状态和失败原因。
2. 让管理员能够生成待确认草稿、查看报告版本状态并下载已生成文件。
3. 报告创建时冻结当前有效材料版本、知识库版本和项目当前规则版本；每个章节记录其输入的规则定义 ID。
4. UI、HTTP API 和 Harness 复用同一个报告服务和同一套覆盖门禁。
5. 没有规则绑定时明确显示业务配置缺失；不自动创建、推荐或推断认证规则。

本切片不实现：

- 任何具体认证规则、规则集或管理员业务配置；
- ONLYOFFICE 编辑器和文档同步；
- 规则编辑器、规则测试台或模型辅助规则判断；
- 用不存在的规则配置伪造“规则已通过”；
- 把材料提取完成误标记为证据处理完成。

## 3. 设计决策

### 3.1 三阶段状态边界

材料处理、证据处理和报告生成保持独立：

```text
材料提取/分块
        ↓
显式“处理证据” → 证据台账 + 知识覆盖
        ↓
显式“生成草稿” → 分章节报告版本
        ↓
显式“确认发布” → 覆盖门禁 + 规则门禁
```

证据处理不依赖规则绑定，可以先完成全文证据和知识覆盖。报告草稿仍保留旧项目兼容性：覆盖完整即可生成，但若没有当前规则绑定，报告必须带有“规则未配置”的可见状态，不能发布为已确认报告。

### 3.2 规则快照与适用范围

创建报告版本时读取当前租户和项目的 `ProjectRuleBinding(status="current")`，保存：

- `rule_set_version_ids_json`：创建瞬间的已绑定规则版本 ID，顺序稳定；
- `rule_definition_ids_json`（章节级）：本章节输入的规则定义 ID，顺序稳定；
- `rule_traceability_status`：`complete`、`not_configured` 或 `incomplete`。

规则版本必须属于当前租户且为已发布版本。章节规则只从绑定版本的启用规则中选择：声明了 `generate_report_sections` 的规则，或未声明工作流节点的通用规则；声明了 `audit_report` 以外文档类型的规则排除。当前审核要素目录没有稳定的信息域字段，因此带信息域的规则暂不按猜测映射到章节，而作为受控规则上下文保留并记录；不得静默丢弃。

本切片只保存并向章节模型暴露规则上下文，不自行运行具体认证规则。规则评价和例外放行仍由后续规则执行切片接入；因此本切片不会把“有规则快照”描述成“规则已通过”。

### 3.3 发布门禁

`calculate_coverage` 的现有材料、分块和审核要素门禁继续有效，并新增规则状态判断：

- 证据处理可以在 `RULE_BINDING_NOT_INITIALIZED` 下运行；
- 草稿生成可以在规则未配置时运行，返回 `rule_traceability_status=not_configured`；
- `publish=true` 或确认发布时，必须存在至少一个当前已发布规则绑定，否则返回 `RULE_BINDING_REQUIRED_FOR_PUBLISH`；
- 规则版本在报告创建后发生迁移，不改变旧报告快照；新报告读取新绑定。

### 3.4 统一入口

新增或扩展的 HTTP 和 Harness 调用都委托给同一服务：

- `process`：项目材料齐备后运行待处理证据块和固定知识检索；已有成功块保持幂等；
- `create_report`：创建新版本、恢复未完成章节，并按请求决定是否发布；
- `report_status`：返回覆盖、报告状态、规则快照状态和章节状态；
- `download_report`：仅返回已写入的报告 blob，不暴露宿主机路径。

## 4. API 与前端交互

### 4.1 API 契约

保留现有路径和响应兼容性，并补充：

```text
POST /api/audit-cases/{case_id}/process
GET  /api/audit-cases/{case_id}/reports
POST /api/audit-cases/{case_id}/reports
GET  /api/audit-cases/{case_id}/reports/{version_id}/download
```

报告响应新增规则快照与追溯状态字段；章节响应新增 `rule_definition_ids`。处理接口继续使用可选 `model_config_id`，缺省时由服务端选择当前租户默认模型。

错误必须使用现有错误映射机制，并保留可操作代码：

- `MATERIAL_PROCESSING_PENDING`：先等待材料提取/分块；
- `EVIDENCE_PROCESSING_FAILED`：只重试未成功块；
- `RULE_BINDING_NOT_INITIALIZED`：仅用于读取当前绑定为空的明确状态；
- `RULE_BINDING_REQUIRED_FOR_PUBLISH`：确认发布缺少绑定；
- `REPORT_NOT_FOUND`、`REPORT_DOWNLOAD_NOT_READY`：报告版本或文件尚未生成。

### 4.2 项目页面

在认证项目详情增加“证据与报告”页签，包含：

- 当前材料、分块、审核要素覆盖率；
- “处理证据”按钮：只在材料提取/分块完成且仍有待处理块时可用；
- 证据处理状态、失败计数和可重试提示；
- 当前规则绑定状态和规则快照警告，不在页面编造规则名称；
- “生成待确认草稿”按钮：覆盖允许时可用；
- 报告版本列表、章节状态、规则/材料/知识快照摘要和下载按钮；
- “确认发布”只在覆盖和规则发布门禁均满足时可用。

请求失败时保留已有材料、覆盖、报告和规则状态；不以空响应覆盖可见数据。

## 5. Harness 衔接

增加仅对已绑定审核项目可见的 `audit_report_generate` 内部能力。Invoker 只使用当前 session 已授权的 `audit_case_id` 和服务端模型配置，不接受模型提供的租户或项目 ID。能力结果只返回状态、版本 ID、章节状态、规则快照状态和受控下载引用，不返回材料全文或宿主机绝对路径。

SOP 的 `generate_report_sections` 节点声明该能力；`output_and_confirm` 继续要求 `audit_report_status` 和人工确认。普通聊天没有审核项目时不得看到或调用该能力。

## 6. 数据迁移与权限

通过现有幂等 SQLite 启动迁移为已有报告表增加可空 JSON/文本字段；旧报告字段保持原值，规则快照状态默认为 `not_configured`，不回填虚构规则。

所有报告、章节、规则绑定和下载查询同时校验 `tenant_id`、`audit_case_id` 和现有项目访问权限。归档项目不可处理材料、生成新报告或发布，但可查看历史报告及其快照。

## 7. 验证策略

后端 TDD 覆盖：

- 处理入口在材料待处理时返回可重试的 pending 状态；
- 已成功证据块不重复调用模型；
- 无规则时草稿状态为 `not_configured`，确认发布被 `RULE_BINDING_REQUIRED_FOR_PUBLISH` 阻止；
- 规则绑定版本和章节规则 ID 在报告创建时冻结，后续迁移不改旧报告；
- 下载严格租户和项目隔离，未生成文件返回稳定错误；
- Harness 只在绑定审核项目上下文中暴露报告生成能力。

前端 TDD 覆盖：

- 证据处理按钮根据覆盖状态启停并保留失败状态；
- 草稿生成、版本刷新、下载入口和规则未配置提示；
- 发布按钮受覆盖和规则门禁共同控制；
- 处理/报告请求失败不会清空已有状态。

验收仍需执行相关后端和前端定向测试、完整回归、Ruff、前端生产构建以及 Windows `scripts/dev_up.ps1 --detach` 启停和 `/api/health`、`/workspace/gallery` 检查。

## 8. 后续切片

规则定义的精确信息域映射、项目数据域装载、确定性评价、强制规则阻断和例外放行属于 Phase 5B，不在本切片假装完成。只有 Phase 5B 接入后，才能对外宣称每个报告结论均已通过当前绑定规则的逐项评价。
