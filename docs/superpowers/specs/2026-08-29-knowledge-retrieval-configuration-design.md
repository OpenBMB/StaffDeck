# StaffDeck 知识检索高级配置设计

日期：2026-08-29
状态：已完成交互评审，待用户复核书面规格

## 1. 背景与问题

StaffDeck 当前已经实现 BM25、Embedding、RRF 和大模型重排，但管理员页面只暴露少量字段：Embedding 地址、模型、API Key、向量维度、候选数量、重排数量和一个生成模型选择项。实际执行中还存在以下限制：

- `HYBRID_KNOWLEDGE_RETRIEVAL_ENABLED` 是启动时读取的环境变量，首次启用要求修改 `.env` 并重启后端。
- OpenAI-compatible Embedding 请求没有发送 `dimensions`，只在响应后校验长度。
- 页面把 1536 作为通用维度默认值，但不同模型支持的维度不同。
- BM25 的 `k1=1.5`、`b=0.75` 和 RRF 的 `k=60` 写死在代码中。
- Reranker 只能使用生成模型或关闭，不能配置独立的专用 Rerank API。
- Embedding 与 Reranker 的连接信息没有完全分离。
- 参数变更是否需要重建向量没有明确判断和安全切换流程。

本设计把检索配置改造成适配器能力驱动的管理系统，并保持现有词法检索和失败降级能力。

## 2. 已核实事实与设计判断

### 2.1 已核实事实

- 智谱 `embedding-3` 官方默认输出 2048 维，支持 256、512、1024、2048 维。
- 智谱 `embedding-3` 单条输入最多 3072 Tokens，单次数组最多 64 条。
- 智谱专用 Rerank API 为 `/rerank`，查询和单条候选最大 4096 字符，最多 128 条候选，并支持 `top_n`。
- 当前 StaffDeck BM25 默认 `k1=1.5`、`b=0.75`，RRF 默认 `k=60`。
- 当前向量存储为 SQLite JSON，查询时由 Python 计算余弦相似度，不存在 HNSW、IVF 或 PQ 索引。

### 2.2 设计判断

- 智谱 `embedding-3` 的 StaffDeck 推荐默认维度采用 1024，以平衡检索质量、存储和计算成本；这不是智谱官方默认值。
- 自定义 Embedding 不再使用统一的 1536 默认值，默认先测试连接并检测实际维度。
- 候选 40、重排 12 是合理通用默认组合，但必须满足重排数量不超过候选数量。
- 配置参数必须由适配器声明并由后端实际消费，不展示后端不支持的伪参数。
- 运行时数据库配置应成为启用检索的唯一依据，不提供网页重启操作系统进程的能力。

## 3. 目标与非目标

### 3.1 目标

- 提供 Embedding、BM25、融合和 Reranker 四个独立设置窗口。
- 用适配器能力注册表描述参数、范围、默认值、连接测试和重建影响。
- 分离 Embedding、专用 Reranker 和对话 Reranker 的模型连接与密钥。
- 保存后热生效，不修改 `.env`，不重启 StaffDeck。
- Embedding 身份变化时版本化重建，并在完整验证后无中断切换。
- 保留 BM25、旧向量和现有词法检索作为失败降级路径。
- 提供稳定错误码、审计、权限控制和可验证的验收标准。

### 3.2 非目标

- 本次不引入 Qdrant、Milvus、Elasticsearch 或 pgvector。
- 本次不展示 HNSW、IVF、PQ 等当前并不存在的向量索引参数。
- 本次不把任意未经校验的 JSON 直接透传给外部模型。
- 本次不通过网页执行系统命令、安装依赖或重启后端进程。
- 本次不解决超大知识库下 SQLite 全量 BM25 和向量扫描的长期性能问题；该问题需要独立的索引后端项目。

## 4. 总体架构

采用“方案 A：适配器能力注册表＋四个独立设置窗口”。

后端为每种适配器注册稳定标识和能力定义，例如：

- `zhipu_embedding`
- `openai_compatible_embedding`
- `zhipu_rerank`
- `generic_rerank`
- `llm_rerank`

能力定义包含：

- 参数名称、类型、范围、枚举和默认值；
- 是否必填、是否敏感、是否只读；
- 是否支持自定义维度；
- 批量数、输入长度和候选数量上限；
- 请求与响应映射；
- 哪些参数影响向量身份；
- 连接测试实现；
- 错误码映射；
- 禁止被扩展参数覆盖的保留字段。

前端通过管理员 API 读取能力定义，按“基本设置”和“高级设置”呈现字段。后端仍是最终校验权威，前端约束只用于交互提示。

## 5. 设置窗口

### 5.1 Embedding 设置

基本字段：

| 字段 | 推荐默认值 | 约束 |
|---|---:|---|
| 适配器 | 按地址和模型识别 | 智谱、OpenAI-compatible、已安装适配器 |
| 接口地址 | 当前值 | 仅允许 HTTP/HTTPS 合法地址 |
| API Key | 当前密钥 | 加密、只写、留空保持不变 |
| 模型 | 当前值 | 非空 |
| 维度模式 | 智谱指定；自定义自动检测 | 自动模式启用前必须测试 |
| 智谱维度 | 1024 | 256、512、1024、2048 |

高级字段：

| 字段 | 推荐默认值 | 约束 |
|---|---:|---|
| 批量大小 | 32 | 1 至适配器上限；智谱上限 64 |
| 请求超时 | 120 秒 | 5 至 600 秒 |
| 最大重试 | 2 | 0 至 5 |
| 初始退避 | 500 毫秒 | 100 至 10000 毫秒，指数退避 |
| 单条输入上限 | 适配器上限 | 智谱为 3072 Tokens |
| 超长策略 | 报错并标记 | 可选安全截断，禁止静默截断 |
| 最低余弦相似度 | 0 | -1 至 1，0 表示不过滤正分结果 |
| 扩展参数 | 适配器定义 | 不得覆盖模型、输入、维度和认证字段 |

连接测试使用固定短文本，发送实际 `dimensions`，校验响应数量、维度、耗时和兼容性。测试不写入正式向量表。

### 5.2 BM25 设置

| 字段 | 推荐默认值 | 约束或作用 |
|---|---:|---|
| 启用 BM25 | 开启 | 可切换为仅向量检索 |
| `k1` | 1.5 | 0.1 至 3.0 |
| `b` | 0.75 | 0 至 1 |
| 候选数量 | 40 | 1 至 500 |
| 最低得分 | 0 | 过滤弱匹配 |
| 分词器 | 中英文增强 | 中文连续词、N-gram、英文和编号保留 |
| 中文 N-gram | 2 | 1 至 3 |
| 精确编号增强 | 开启 | 标准号、条款号和混合编号 |
| 查询词去重 | 开启 | 防止重复词重复加权 |
| 停用词过滤 | 关闭 | 可启用内置表和自定义表 |
| 正文权重 | 1.0 | 0 至 10 |
| 摘要权重 | 0 | 0 至 10，默认保持现有行为 |
| 来源名称权重 | 0 | 0 至 10，默认保持现有行为 |

字段权重启用后，后端必须对正文、摘要和来源分别评分后求加权和；不能只保存配置。

### 5.3 混合融合设置

| 字段 | 推荐默认值 | 约束或作用 |
|---|---:|---|
| 检索模式 | BM25＋向量 | 也支持仅 BM25、仅向量 |
| BM25 召回数 | 40 | 1 至 500 |
| 向量召回数 | 40 | 1 至 500 |
| 融合算法 | 加权 RRF | 本阶段唯一支持算法 |
| RRF `k` | 60 | 1 至 1000 |
| BM25 权重 | 1.0 | 0 至 10 |
| 向量权重 | 1.0 | 0 至 10 |
| 融合后候选数 | 40 | 不超过候选并集 |
| 去重依据 | 切片 ID | 固定安全规则 |
| 单路失败降级 | 开启 | 固定安全规则 |

本阶段不实现线性分数融合，因为 BM25 和余弦分数未经过同尺度校准。

### 5.4 Reranker 设置

模式：专用 Rerank API、对话/生成模型重排、不重排。

通用字段：

| 字段 | 推荐默认值 | 约束或作用 |
|---|---:|---|
| 输入候选数 | 40 | 1 至适配器上限；智谱最多 128 |
| 重排返回数 | 12 | 1 至输入候选数 |
| 最低相关性分数 | 0 | 0 至 1 |
| 查询最大长度 | 4096 字符 | 受适配器限制 |
| 单候选最大长度 | 2000 字符 | 200 至 10000 |
| 请求超时 | 120 秒 | 5 至 600 秒 |
| 最大重试 | 2 | 0 至 5 |
| 失败策略 | 保留 RRF 顺序 | 固定安全默认 |

专用 Rerank API 独立保存适配器、地址、加密 API Key、模型、`top_n`、是否返回文档、是否返回原始分数和适配器扩展参数。

对话模型重排独立保存 API 协议、地址、加密 API Key、模型、温度、输出 Token 上限、输入预算和提示词模板。默认温度为 0、最大输出为 2048 Tokens、输入预算为 32000 Tokens。响应必须通过严格 JSON、候选 ID 白名单、重复 ID 和未知 ID 校验。

## 6. 页面交互

知识库页面显示四张摘要卡：Embedding、BM25、混合融合和 Reranker。顶部显示启用状态、活动配置版本、活动模型与维度、待重建状态、最近测试时间和降级状态。

每个设置窗口包含：

- 基本设置页签；
- 高级设置页签；
- 测试连接；
- 恢复该窗口推荐值；
- 取消；
- 应用到页面草稿。

单个窗口确认只更新浏览器草稿。主页面统一提供：保存草稿、测试全部连接、查看变更、保存并应用、重建向量和回滚。

“保存并应用”是原子操作：任何配置组校验失败时，现有活动配置保持不变。Embedding 身份变化时按钮改为“保存并开始重建”，并显示模型、维度和预计切片数量差异。

## 7. 数据模型与迁移

继续使用 `knowledge_retrieval_configs` 作为主配置表，增加：

- `schema_version`
- `revision`
- `status`：`draft`、`pending_index`、`active`、`archived`、`failed`
- `embedding_adapter`
- `embedding_options_json`
- `bm25_options_json`
- `fusion_options_json`
- `reranker_adapter`
- `reranker_base_url`
- `reranker_api_key_encrypted`
- `reranker_model`
- `reranker_options_json`
- `last_tested_at`
- `tested_fingerprint`
- `activated_at`
- `last_error_code`

Embedding、专用 Reranker 和对话 Reranker 使用不同的加密密钥字段或分区；任何 JSON 配置中不得存储明文密钥。

每个租户最多一个 `active` 和一个 `pending_index` 配置。运行时参数变更在活动配置上递增 `revision`；如果同时存在待重建配置，相同的 BM25、融合和 Reranker 参数同步到待重建配置。Embedding 身份变化创建新配置 ID，因此新旧向量可以继续通过现有 `retrieval_config_id` 隔离。

旧配置迁移规则：

- 保留现有密钥和向量，不自动删除。
- 写入当前兼容默认值：BM25 `1.5/0.75`、RRF `60`、候选 40、重排 12。
- 现有 LLM Reranker 迁移为对话模型模式。
- 新建智谱 `embedding-3` 配置默认 1024 维。
- 已有“智谱 `embedding-3`＋1536 维”配置不静默修改，标记为不受支持，要求测试并版本化重建。
- `HYBRID_KNOWLEDGE_RETRIEVAL_ENABLED` 保留为废弃兼容字段，但不再控制运行时启用。

## 8. 热生效与版本化重建

数据库中状态为 `active` 且验证有效的配置是唯一运行时依据。BM25、融合、阈值、超时、重试和 Reranker 参数保存后立即生效，不需要修改 `.env` 或重启服务。

Embedding 指纹包括适配器、规范化地址、模型、维度和所有影响向量输出的适配器参数。API Key、超时、重试和批量大小不进入指纹。

指纹变化流程：

1. 新配置保存为 `pending_index`。
2. 现有 `active` 配置继续服务。
3. 后台按新配置 ID 生成新向量。
4. 校验切片覆盖率、维度和失败项。
5. 全部必需切片就绪后，在单个数据库事务中把旧配置设为 `archived`、新配置设为 `active`。
6. 失败时保留旧活动配置，并把新配置标记为 `failed` 或可继续重试。

切换事务执行前，把活动配置中最新的 BM25、融合和 Reranker 运行时参数合并到待切换配置，避免重建期间的参数编辑丢失。

旧配置及向量默认保留用于回滚，后续清理必须是独立、显式和可审计操作。

## 9. 权限、安全与审计

只有租户管理员可以读取管理配置、测试连接、启停检索、发起重建、切换和回滚。普通成员只能消费检索结果。

安全规则：

- 密钥加密存储，读取只返回掩码和是否已配置。
- 日志、错误和审计记录不得包含密钥或完整敏感上游响应。
- 连接测试限流，并限制超时和最大响应体。
- 外部 HTTP 调用禁止自动重定向。
- 扩展参数不得覆盖认证头和核心请求字段。
- 保存携带 `revision`，通过乐观锁防止管理员互相覆盖。
- 审计记录操作者、时间、变更字段、测试结果、重建和切换事件，不记录密钥值。
- 因为本地模型是有效使用场景，管理员配置允许回环和局域网地址；风险通过权限、限流、超时、响应限制和审计控制。

## 10. 错误处理与降级

至少提供以下稳定错误类型：

- 配置或版本冲突；
- 地址或协议错误；
- 认证失败；
- 模型不存在；
- 维度不支持或不匹配；
- 输入超限；
- 超时、限流或临时网络故障；
- Reranker 响应格式、未知 ID 或重复 ID 错误；
- 重建部分失败或切换失败。

错误响应包含中文说明、稳定错误码、出错阶段、可否重试、建议动作和脱敏后的上游请求 ID。

降级规则：

- Embedding 失败时使用 BM25。
- BM25 无结果时仍允许向量结果。
- Reranker 失败时保留 RRF 顺序。
- 新向量重建失败时继续使用旧活动配置。
- 两路混合检索均失败时回退现有词法检索。
- 认证失败、维度错误和模型不存在等确定性错误不自动重试。
- 超时、限流和临时网络故障按适配器参数退避重试。

## 11. 实施阶段

- Phase 1：配置结构、迁移、能力注册、Embedding 和 BM25 参数。
- Phase 2：加权 RRF、专用 Rerank API 和独立 LLM Reranker。
- Phase 3：版本化重建、切换、回滚和状态监控。
- Phase 4：四个设置窗口、完整迁移、端到端验证和文档更新。

每个阶段按 TDD 实施，并保持主服务可启动、现有检索可降级使用。

## 12. 测试与验收

### 12.1 后端单元测试

- 智谱 1024 维请求包含 `dimensions: 1024`。
- 自动维度测试保存实际维度。
- 智谱适配器拒绝 1536 维。
- BM25 参数、字段权重、编号增强和 N-gram 实际改变评分。
- 加权 RRF 按配置计算。
- 重排数量不超过候选数量。
- 专用 Rerank API 请求和响应映射正确。
- LLM Reranker 使用独立连接并校验输出。
- 各失败路径按规则降级。

### 12.2 API 与数据库测试

- 旧配置自动迁移且不删除旧向量。
- 三类密钥隔离、加密、掩码和留空保持逻辑正确。
- 普通成员不能管理配置。
- 四组配置原子保存，修订冲突可检测。
- Embedding 指纹变化创建待重建配置。
- 重建成功后原子切换，失败后旧配置仍活动。
- 回滚不误删向量。

### 12.3 前端测试

- 四张摘要卡和四个设置窗口正确显示。
- 基本/高级字段和适配器能力联动。
- 智谱只显示合法维度，自定义模型支持自动检测。
- 专用与 LLM Reranker 展示不同连接字段。
- 字段错误、变更摘要和重建提示正确。
- 密钥留空保持原值。
- 保存、测试、重建、取消和回滚按钮状态正确。

### 12.4 端到端验收

1. 不修改 `.env`、不重启 StaffDeck。
2. 在网页配置智谱 `embedding-3` 为 1024 维。
3. 测试连接显示实际 1024 维。
4. 对测试知识文档完成向量化。
5. 用固定查询验证 BM25、向量和加权 RRF。
6. 分别验证专用和 LLM Reranker。
7. 制造上游故障并验证降级。
8. 把维度从 1024 改为 512，验证旧配置继续服务，重建完成后切换。
9. 验证 `/api/health` 和 `/workspace/gallery`。
10. 完成实际浏览器页面的视觉和交互检查。

## 13. 完成定义

只有在以下条件全部满足时才视为完成：

- 所有新参数都有后端消费逻辑和自动化测试；
- 不再需要环境变量启用或后端重启；
- 智谱维度请求、检测和重建流程可验证；
- Embedding 与两类 Reranker 连接和密钥隔离；
- 旧配置迁移和旧向量回滚可用；
- 失败降级不会中断现有知识检索；
- 前后端测试、端到端验收、健康检查和页面检查全部通过；
- README、中文 README 和 `.env.example` 与新行为一致。
