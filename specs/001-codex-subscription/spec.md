# Feature Specification: Codex Subscription Models

**Feature Branch**: `001-codex-subscription`  
**Created**: 2026-08-28  
**Status**: Draft  
**Input**: User description: "在保留 API Key 模型的同时，新增可复用 ChatGPT/Codex 订阅的认证和模型使用方式；新增模型时由用户选择认证方式，两种方式可并存且可配置多个模型。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 添加订阅模型 (Priority: P1)

租户管理员在新增模型时选择“ChatGPT 订阅（Codex）”，完成一次浏览器授权后，为已授权的订阅选择一个模型并保存。该配置不要求、也不显示 API Key 输入。

**Why this priority**: 这是让订阅能力真正成为可选模型来源的最小可用路径。

**Independent Test**: 在没有 API Key 的前提下，已完成订阅授权的管理员可保存一条未启用或已通过验证的订阅模型配置，并在列表中看到其认证方式与安全状态。

**Acceptance Scenarios**:

1. **Given** 管理员尚未完成本机 Codex 订阅授权，**When** 选择订阅认证方式，**Then** 系统说明需要授权且不允许把该配置作为已验证模型启用。
2. **Given** 管理员已完成授权，**When** 填写名称与模型并保存，**Then** 系统保存不含 API Key 的订阅模型配置。
3. **Given** 订阅授权被取消、过期或不可用，**When** 管理员测试或启用订阅模型，**Then** 系统给出可重新授权的明确提示且不启用该模型。

---

### User Story 2 - 用订阅模型执行对话 (Priority: P2)

管理员将已验证的订阅模型设为默认模型或绑定到数字员工后，StaffDeck 使用该订阅完成文本和流式对话，而不是调用 API Key 计费接口。

**Why this priority**: 保存认证配置不产生价值，能在现有会话中运行才完成用户目标。

**Independent Test**: 使用受控的本机 Codex 运行时替身，验证模型测试与一次文本/流式请求都通过订阅运行时完成，并能把成功内容返回给现有调用方。

**Acceptance Scenarios**:

1. **Given** 一条已验证并启用的订阅模型，**When** StaffDeck 请求文本响应，**Then** 返回订阅运行时产生的文本。
2. **Given** 一条已验证并启用的订阅模型，**When** StaffDeck 请求流式响应，**Then** 按现有流式消费方式产生增量文本并正常结束。
3. **Given** 当前默认模型是订阅模型，**When** 其他既有业务请求模型，**Then** 它们遵循与 API Key 模型相同的启用、默认与授权边界。

---

### User Story 3 - 与 API Key 模型共存 (Priority: P3)

管理员可在同一租户中保留多个 API Key 模型和多个订阅模型，并可分别编辑、测试、启用、停用或设为默认，不会破坏现有 API Key 配置。

**Why this priority**: 用户明确要求两种模式同时兼容且可配置多个模型。

**Independent Test**: 在同一租户创建一条 API Key 模型和两条订阅模型，验证三条均可显示、认证字段正确隔离，且切换默认模型不会修改其他配置。

**Acceptance Scenarios**:

1. **Given** 已有 API Key 模型，**When** 新增订阅模型，**Then** 原 API Key 配置和其可用性保持不变。
2. **Given** 同一已授权订阅，**When** 保存多个不同模型名的订阅配置，**Then** 每条配置独立显示且均引用同一安全的本机授权状态。
3. **Given** 管理员编辑 API Key 模型，**When** 选择 API Key 认证方式，**Then** 原有 API Key、Base URL、协议和额外参数交互保持兼容。

### Edge Cases

- 本机未安装、未启动或不支持所需订阅能力时，系统不得把模型误标为可用，并提供可操作的本机修复提示。
- 浏览器授权被用户取消或返回失败时，不创建可用模型，也不显示或记录授权码、令牌、Cookie 或回调内容。
- 订阅模型运行时遇到配额或认证失效时，保留原配置但取消其可信/启用状态，要求重新测试或授权。
- 订阅模式不接受 API Key、Base URL 或供应商专用额外参数作为运行凭据；API Key 模式维持现有验证规则。
- 订阅模型不可用不得影响同一租户中其他 API Key 模型的选择、测试或对话。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 让租户管理员在新建和编辑模型时明确选择“API Key”或“ChatGPT 订阅（Codex）”认证方式。
- **FR-002**: 系统 MUST 保留现有 API Key 模型的创建、编辑、验证、启用、停用、默认选择和调用行为。
- **FR-003**: 系统 MUST 为订阅模式提供账户状态、开始授权、取消授权、重新授权和退出授权的管理入口。
- **FR-004**: 系统 MUST 在订阅模式下仅保存模型配置与非敏感授权状态，不得在数据库、接口响应、前端状态或日志中保存或返回原始授权令牌、授权码、Cookie 或回调地址。
- **FR-005**: 系统 MUST 允许同一已授权的本机订阅被多个订阅模型配置复用，且这些配置可与 API Key 模型同时存在。
- **FR-006**: 系统 MUST 让订阅模型经过一次可重复的连接验证后，才能启用或设为默认模型。
- **FR-007**: 系统 MUST 依据模型配置的认证方式选择正确运行通道；订阅模型的文本、流式文本与结构化文本请求必须返回给现有模型调用方可消费的结果或明确错误。
- **FR-008**: 系统 MUST 在订阅认证不可用、取消、过期、配额不足或运行时不可用时，返回不含敏感信息的可操作错误，并不得自动切换到 API Key 模型或其他订阅。
- **FR-009**: 系统 MUST 在模型列表、详情和测试结果中显示认证方式及订阅授权状态，同时继续掩码显示 API Key 模式的密钥。
- **FR-010**: 系统 MUST 把订阅认证管理和模型配置操作限制为当前租户管理员，并继续执行现有租户隔离规则。

### Key Entities

- **模型配置**: 一个可选择、验证、启用或设为默认的模型条目，包含认证方式、模型标识、运行参数与可信状态。
- **订阅授权状态**: 当前本机 Codex 订阅是否可用及其可安全展示的状态；不包含可复原的凭据。
- **订阅模型引用**: 使用订阅授权状态的模型配置；多个引用可以共享同一已授权订阅，但各自拥有独立名称、模型标识、启用状态和默认状态。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 已授权管理员能在 3 分钟内创建并验证一条无 API Key 的订阅模型配置。
- **SC-002**: 在同一租户中，一条 API Key 模型和至少两条订阅模型可同时显示，并能独立完成默认模型切换。
- **SC-003**: 受控验收环境中，订阅模型的文本、流式文本和结构化文本验证均返回可消费结果或明确的非敏感失败状态。
- **SC-004**: 自动化测试证明任一公开接口、模型配置读取和运行错误均不含原始订阅凭据。
- **SC-005**: 现有 API Key 模型配置与验证回归测试继续通过。

## Assumptions

- 第一阶段目标为本机桌面/单用户运行：一台设备只复用该设备的一个 Codex 订阅登录状态；多账号订阅切换和服务端共享凭据不在范围内。
- 用户完成浏览器中的 OpenAI/Codex 交互；StaffDeck 不要求用户手动复制命令、授权码、JSON、Cookie 或回调地址。
- 本机具备受支持的 Codex 运行环境，且其订阅权益、模型可用性与限额由 OpenAI/Codex 账户决定。
- 现有 API Key 供应商、协议、Base URL 与额外参数能力均继续受支持；本功能不会把 ChatGPT 订阅转换为 API Key 或 API 额度。
- 本次不覆盖服务器集群、远程多租户共享订阅、用量结算面板或多个 OpenAI 订阅账户的管理。
